# Reports API

Reports are the core of the Civic Issue Resolution System (CSCRS). They document citizen-submitted civic issues, which are processed through an automated verification and classification pipeline. This pipeline uses AI-based computer vision (YOLO) and verification checks (EXIF, metadata, and quality analysis) before resolving assignments, priorities, and duplicate reports.

---

## Report Enumerations

The following enums are serialized and exposed via the Reports API:

### `ReportStatus`
Defines the state lifecycle of a report.

| Value | Meaning |
| :--- | :--- |
| `Pending` | Report created, waiting for auto-assignment or manual review. |
| `Assigned` | Worker assigned to the report. |
| `In Progress` | Worker has started working on site. |
| `Resolved` | Worker has submitted a resolution (awaiting verification). |
| `Verified` | Resolution verified by department/city admin. |
| `Closed` | Ticket closed successfully. |
| `Cancelled` | Cancelled by an administrator (with cancellation reason). |
| `Rejected` | Verification failed (e.g. invalid report). |

### `Priority`
Determines execution urgency, calculated dynamically by the priority engine.

| Value | Meaning |
| :--- | :--- |
| `Low` | Low priority issue. |
| `Medium` | Medium priority issue. |
| `High` | High priority issue. |
| `Critical` | Urgent intervention required. |

### `VerificationDecision`
The decision generated by the verification risk engine.

| Value | Meaning |
| :--- | :--- |
| `PASS` | Image verification passed successfully. |
| `REVIEW` | Image has minor anomalies (marked for manual review during prediction but rejected during submission). |
| `REJECT` | Image rejected due to critical metadata missing or poor quality metrics. |

### `ReportCancellationReason`
Administrative reasons provided during report cancellation.

| Value | Meaning |
| :--- | :--- |
| `DUPLICATE` | Issue was already reported. |
| `ALREADY_RESOLVED` | Issue has already been resolved. |
| `NOT_A_CIVIC_ISSUE` | The image does not show a valid civic issue. |
| `FALSE_REPORT` | Spam or false representation. |
| `OUTSIDE_JURISDICTION` | Location is outside city boundaries. |
| `OTHER` | Miscellaneous reasons specified in remarks. |

## `POST /api/v1/report`

### Purpose
Allows a citizen to submit a new report. The submission goes through image metadata (EXIF) verification, image quality checks, YOLO civic issue detection, duplicate report detection, priority scoring, and auto-assignment.

### Roles / Authorization
* Citizen role.

### Authentication
* Bearer Access Token required.

### Headers
* `Authorization: Bearer <access_token>`
* `Content-Type: multipart/form-data`

### Path Parameters
* `Not applicable`

### Query Parameters
* `Not applicable`

### Request Body / Form Data

| Field | Type | Required | Constraints / Validation | Description |
| :--- | :--- | :---: | :--- | :--- |
| `file` | File (Binary) | Yes | File type: Multipart File | The original photo of the civic issue. |
| `description` | String | No | Form Parameter | Optional text description of the issue. |

### Validation Rules
* **File Constraints:** Validates file size against `MAX_FILE_SIZE` (10MB). File extensions must be `.jpg`, `.jpeg`, `.png`, or `.webp`. Content-Type must match `image/jpeg`, `image/png`, or `image/webp`. Magic-byte signature checking is enforced.
* **AI Image Verification:** Predicts EXIF and image quality. If the risk engine evaluation decision is not `"PASS"` (i.e. if the decision is `"REVIEW"` or `"REJECT"` due to missing metadata or poor quality flags), the submission is rejected with HTTP `400 Bad Request`.
* **AI Issue Detection:** Runs YOLOv8 civic issue detection. If no detections are found, or the inference fails, unlinks saved images and raises HTTP `400 Bad Request` with `"No civic issue detected in the image."`.
* **Duplicate Detection:**
  * Candidate reports must share the same `issue_type` and be in active statuses (`Pending`, `Assigned`, `In Progress`).
  * **Geographic threshold:** Candidates must be within **8.0 meters** (`DUPLICATE_REPORT_RADIUS_METERS`) of the submission coordinates.
  * **Visual similarity check:** If enabled, the OpenCLIP cosine similarity score must be `>= 0.82` (`DUPLICATE_SCENE_THRESHOLD`).
  * If a duplicate is found:
    * If the caller is the original creator: aborts with `409 Conflict`.
    * If the caller has already supported it: aborts with `409 Conflict`.
    * Otherwise: increments `support_count`, registers citizen support, logs audit details, deletes the newly uploaded files, and returns a successful response indicating duplicate supported.

### Rate Limit
* Configured rate limit: `60 per hour` (Effective: 60 requests per hour per IP/User).

### Business Flow
1. Receives and validates upload file size, extension, and binary magic-bytes.
2. Saves file to local `uploads/` directory with a generated UUID-based filename.
3. Decodes EXIF and evaluates image parameters. Computes weighted risk: `exif` (70%), `quality` (25%), `duplicate` (5%).
   * Rejects with `400` if decision is not `"PASS"`.
4. Runs YOLOv8 object detector. Extracts detections containing class name, confidence, and bounding box. Rejects with `400` if no detections.
5. Maps class name to municipal department configuration mapping:
   * `"Garbage"` $\rightarrow$ `"Sanitation"`
   * `"Road Damage"` $\rightarrow$ `"Roads"`
   * `"Manhole"` $\rightarrow$ `"Roads"`
   * `"Waterlogging"` $\rightarrow$ `"Drainage"`
   * `"Damage Electric Pole"` $\rightarrow$ `"Electricity"`
   * `"Damage Street Light"` $\rightarrow$ `"Street Lighting"`
6. Resolves decimal GPS coordinate values. If found, queries for duplicates. If duplicate is matched:
   * Validates duplicate ownership. If user is owner/supporter, throws `409`.
   * Otherwise, registers citizen support, commits transaction, cleans up new upload files, and returns duplicate payload with `200 OK`.
7. If not duplicate, saves report record in `reports` database table (initial status: `Pending`).
8. Computes Priority score using:
   * **AI Risk Score:** `risk_score >= 0.80` (+60), `>= 0.60` (+45), `>= 0.40` (+30), else (+15).
   * **Supports count:** `>= 50` (+40), `>= 25` (+30), `>= 10` (+20), `>= 5` (+10), else (+0).
   * **Thresholds:** `score >= 90` (Critical), `score >= 60` (High), `score >= 35` (Medium), else (Low).
9. Persists original image path, annotated image path (from YOLO visualization), and AI detection fields.
10. Automatically triggers worker assignment:
    * Looks up active workers in the department. Selects worker with the lowest active assignment workload.
    * Updates assignment table, shifts report status to `Assigned`, and notifies the worker.
    * If no worker is available, catches `404`, keeps report status as `Pending`, and appends an allocation disclaimer message.
11. Returns success response.

### Success Response
* **HTTP Status:** `200 OK`
* **Response Model:** Raw Dictionary (if new report is created).

| Field | Type | Description |
| :--- | :--- | :--- |
| `success` | Boolean | Always `true`. |
| `message` | String | Success confirmation message. |
| `report_id` | Integer | Database key of the created report. |
| `report_number` | String | Unique serialized report number. |
| `verification` | Dictionary | Contains verifier risk score, decision flags, and verification parameters. |
| `ai` | Dictionary | Contains model metadata, annotated image path, and a summary list of object detections. **Privacy:** The `polygon` attribute is excluded from the returned detections. |
| `processing_time` | Float | Server execution duration in seconds. |

### Error Responses
| HTTP Status | Condition | Response / Detail |
| :---: | :--- | :--- |
| **400** | Image rejected during verifier analysis (decision is not PASS). | `{"detail": {"success": false, "message": "Image rejected during verification.", "verification": {"risk_score": 0.65, "decision": "REJECT", "verification_passed": false, "manual_review": false, "flags": ["BLURRY", "NO_EXIF"]}, "detections": []}}` |
| **400** | No civic issue detected in YOLO inference. | `{"detail": "No civic issue detected in the image."}` |
| **401** | Missing/invalid credentials. | `{"detail": "Invalid or expired token."}` |
| **409** | User attempts to submit a duplicate they already reported. | `{"detail": {"success": false, "message": "You have already reported this civic issue.", "report_id": 15, "report_number": "REP-2026-0034", "status": "Pending", "priority": "Medium", "support_count": 1}}` |
| **409** | User attempts to support a duplicate they already support. | `{"detail": {"success": false, "message": "You have already reported/supported this civic issue.", "report_id": 15, "report_number": "REP-2026-0034", "status": "Pending", "priority": "Medium", "support_count": 2}}` |
| **413** | File size exceeds 10MB limit. | `{"detail": "File size exceeds allowed limit."}` |
| **422** | Required binary file input parameter missing. | `{"detail": [{"loc": ["body", "file"], "msg": "field required", "type": "value_error.missing"}]}` |
| **429** | Limit of 60 requests per hour exceeded. | `{"success": false, "message": "Too many requests. Please try again later.", "error_code": "RATE_LIMIT_EXCEEDED"}` |

### Possible HTTP Status Codes
* `200`, `400`, `401`, `409`, `413`, `422`, `429`, `500`

### Database / State Changes
* Adds record to `reports` table.
* Increments `support_count` and adds record to `report_supports` on duplicates.
* Inserts records to `report_images` and `report_detections` tables.
* Inserts new assignment and audit log entries on success.

### Side Effects
* Writes original and annotated image files to filesystem storage.
* Sends notification alerts to target workers.

### Frontend Integration Notes
* The payload must be sent with `multipart/form-data` encoding.
* The form field containing the binary file must be named **`file`**.
* The application should parse the response keys `duplicate` and `supported_existing_report`. If duplicate is true, redirect the user directly to the existing report details page.

## `POST /api/v1/reports/{report_id}/cancel`

### Purpose
Allows a Department Admin to cancel an active report.

### Roles / Authorization
* Department Admin role. Scoped strictly to reports assigned to the admin's `department_id`.

### Authentication
* Bearer Access Token required.

### Headers
* `Authorization: Bearer <access_token>`
* `Content-Type: application/json`

### Path Parameters

| Name | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `report_id` | Integer | Yes | Database key identifier of report. |

### Query Parameters
* `Not applicable`

### Request Body / Form Data

| Field | Type | Required | Constraints / Validation | Description |
| :--- | :--- | :---: | :--- | :--- |
| `reason_type` | String | Yes | Must match `ReportCancellationReason` | Categorized cancellation reason. |
| `remarks` | String | No | Optional, max 500 characters | Additional remarks. |

### Validation Rules
* **Pydantic Validation:** Mismatched enums result in HTTP `422`.
* **State Verification:** Report must be in one of the following active states: `Pending`, `Assigned`, or `In Progress`. If the report is in other states (e.g. `Resolved`, `Verified`, `Closed`), throws `400 Bad Request`.
* **Duplicate Cancellation Gate:** If status is already `Cancelled`, throws `400`.

### Rate Limit
* `No endpoint-specific rate limit verified.`

### Business Flow
1. Authenticates Department Admin and validates department boundaries.
2. Checks report status and details. Throws `400` or `403` if rules are violated.
3. Shifts report status to `Cancelled`.
4. Checks if there is an active worker assignment for this report. If yes:
   * Sets the active assignment status to `Cancelled`.
   * Sets assignment remarks: `"Cancelled by Department Admin | Reason: <reason> | Remarks: <remarks>"`.
   * Sets worker profile availability flag back to `True` (`is_available = True`).
   * Sends an `ASSIGNMENT_CANCELLED` notification to the worker.
5. Sends a `REPORT_CANCELLED` notification to the submitting citizen.
6. Writes audit log trace `REPORT_CANCELLED_BY_DEPARTMENT`.
7. Commits database changes and returns cancellation summary payload.

### Success Response
* **HTTP Status:** `200 OK`
* **Response Model:** Raw Dictionary.

| Field | Type | Description |
| :--- | :--- | :--- |
| `success` | Boolean | Always `true`. |
| `message` | String | `"Report cancelled successfully."` |
| `report_id` | Integer | ID of the report. |
| `report_number` | String | Number of the report. |
| `status` | String | Target status (`Cancelled`). |
| `reason` | String | Cancellation reason string. |

### Example Success Response
```json
{
  "success": true,
  "message": "Report cancelled successfully.",
  "report_id": 42,
  "report_number": "REP-2026-0089",
  "status": "Cancelled",

}
```

### Error Responses
| HTTP Status | Condition | Response / Detail |
| :---: | :--- | :--- |

### Possible HTTP Status Codes

### Database / State Changes

* Updates worker availability to `True` on assigned worker profile.
* Adds audit log trace and notification entries.

### Roles / Authorization

### Headers

### Path Parameters

### Query Parameters

### Request Body / Form Data

### Rate Limiting

### Validation Rules
* Caller must hold `DEPARTMENT_ADMIN` role.
* Caller must have an active, non-blocked account.

### Business Logic
